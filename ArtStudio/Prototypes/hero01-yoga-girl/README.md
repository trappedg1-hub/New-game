# YOGA GIRL — изолированный предпросмотр движения

**Статус:** на проверке; анимация не утверждена и в игру не внедрена. Статичный исходник утверждён отдельно. Основа — PixiJS и суставной skinning утверждённой V3; здесь новые точки суставов, маски и движения для позы йоги. Исходник не масштабировался и не изменялся: `../../Generated/Approved/HERO-01_outfit05_yoga_girl.png`, 1534 × 2733, SHA-256 `5cd0f5faca1f86fa3f0dfca6429615a877cc98b60c5af542ccbb99a1ff16a317`.

**Предпросмотр на Vercel:** https://hero01-yoga-girl-prototype.vercel.app/ — отдельный проект `hero01-yoga-girl-prototype`; deployment `dpl_31YQdfmpASFBihL24p1VjnWDEr6E` (READY/PROMOTED), код `f3f7ef051bf62c8305997e876df2170c73cf2e9a`. Публикация предназначена только для оценки и не является внедрением в игру.
В прототипе четыре независимые цепи из трёх суставов, мягкая подложка корпуса, движение хвоста и ткани, моргание и 13 зон реакции. Края рук у шорт и тень между коленями закреплены, чтобы не раскрывать матирование при небольших движениях. Доступны пауза, интенсивность, крупный план и сравнение с оригиналом. Автоматическое уменьшение движения учитывает системную настройку `prefers-reduced-motion`.

## Запуск и проверка

```sh
npm ci
npm run dev -- --port 5188 --strictPort
# В другом терминале:
npm test
npm run build
CHROME_PATH=/path/to/chromium npm run qa:browser
```

Браузерный QA ожидает локальный сервер на порту 5188; адрес можно изменить через `PREVIEW_URL`. Нужен Chromium с WebGL. `?qa=1` включает диагностический интерфейс, который не активируется в обычном режиме. Для пересоздания derived-слоёв нужен Python с пакетами из `scripts/requirements.txt` и сохранённая проба закрытых глаз `artifacts/closed_eyes_study.png`:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r scripts/requirements.txt
python scripts/build-assets.py
```

Генератор проверяет SHA исходника, записывает только `public/derived`, выравнивает глазные патчи по исходному лицу и проверяет нейтральную RGB-композицию. Для ускорения пропускаются только заведомо прозрачные ячейки с запасом 32 пикселя для фильтрации, а в режиме полного роста за пределы WebGL-холста вынесены пустые боковые поля. Размеры текстур, масштаб персонажа и плотность видимой сетки не уменьшены.

## Результаты локальной проверки

- `npm test`: 8/8; `npm run build`: успешно, с предупреждением Vite о размере JS-чанка.
- В Chromium проверены 1624 конфигурации: оба 12-секундных цикла по 60 выборок/с при 100% и 150%, отдельные и одновременные предельные положения суставов, 13 зон × 3 варианта реакций × 4 положения цикла. Минимальное ориентированное произведение треугольников корпуса — 454.77, слоёв — 283.83; отрицательных или вырожденных проверенных ячеек нет. На контрольных точках максимальный шаг за 1/60 с — 0.122 исходного пикселя. Это геометрические проверки, а не визуальная проверка каждого возможного состояния.
- Нейтральная RGB-композиция слоёв в Python: средняя и максимальная ошибка 0. WebGL-сравнение с исходником при 384 × 650: среднее абсолютное отличие 0.565/255, максимум 40/255; побайтовой идентичности RGBA в браузере нет. На стыке 0/12 секунд два WebGL-кадра совпали. Оптимизированная и полная сетки дали одинаковые пиксели в 6 проверенных кадрах, включая моргание и крайние позы.
- Реальные события Playwright: 13/13 зон мышью и 13/13 касанием в эмуляции; также проверены перетаскивание без ложного клика, горизонтальный режим, пауза, ручное моргание, переключатели и reduced-motion. Ошибок консоли и запросов при проверке не было.
- Опубликованный URL и 16 JS/PNG/JSON-файлов сравнены по SHA-256 с локальной сборкой; запуск, моргание, замыкание цикла и 13 касаний прошли в iPhone-sized WebKit в [Actions 42019483001](https://github.com/trappedg1-hub/New-game/actions/runs/42019483001). Это браузерная эмуляция, не физическое устройство. Повторная проверка: `npm run build && npx playwright-core install --with-deps webkit && node scripts/public-qa.mjs`.
- **Производительность ещё не подтверждена на устройстве:** headless Chromium с программным SwiftShader показал примерно 15.0 FPS в desktop-окне 1280 × 1050 и 11.9 FPS в эмуляции 390 × 844; это не тест GPU реального телефона. В отдельных аналогичных запусках V3 показала около 13.4 FPS на desktop и 14.7 FPS в мобильной эмуляции, но нагрузка и площадь персонажа различаются. Требование сохранить FPS и плавность на реальных устройствах остаётся открытым.

## Ограничения до утверждения

Источник — одно плоское изображение; скрытые участки и контактные тени восстановлены приблизительно. Диапазон суставов намеренно ограничен вокруг исходной позы. Проверенные крайние кадры и крупный план моргания просмотрены, но это не гарантия отсутствия швов, мерцания или анатомических недостатков при всех состояниях и на всех устройствах. Мимика в этом варианте ограничена морганием; дополнительные выражения V3 для костюма пока не адаптированы. Цикл корпуса длится 12 секунд, расписание автоматического моргания — 24 секунды. Физические устройства и Safari не проверялись. Нужны пользовательская оценка движения и отдельная проверка производительности до любого внедрения.
