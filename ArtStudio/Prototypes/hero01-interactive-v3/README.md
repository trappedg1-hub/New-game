# HERO-01 · интерактивный прототип V3

Изолированный эксперимент на основе V1 из [`../hero01-idle/`](../hero01-idle/); V2 не использовался как основа. V1, V2 и утверждённые изображения не изменяются. V3 **не является утверждённым финальным ригом**.

Публичная production-ссылка отдельного проекта: **https://hero01-interactive-v3-prototype.vercel.app/**. Какая именно версия опубликована, указано в [`PROGRESS.md`](PROGRESS.md); локальный исходный код может быть новее публичной версии.

## Запуск

```sh
cd ArtStudio/Prototypes/hero01-interactive-v3
npm ci
npm run dev                 # Vite на 0.0.0.0:5173
npm test && npm run build
```

Для сборки нужен весь репозиторий: исходное изображение находится в `ArtStudio/Generated/Approved/`. Используется PixiJS **7.4.3**, как в V1. На мобильных touch-экранах плотность WebGL ограничена 1.5×, на desktop — 2×.

## Использование

Режим «Персонаж» увеличивает область касания; «Сравнение» показывает статичный оригинал и анимацию рядом. Доступны полный рост/лицо, пауза, ручное моргание и сила движения. Тринадцать областей реагируют на мышь и касания; клавиши 1–9 на сфокусированной области — альтернативный ввод. При `prefers-reduced-motion` idle начинает на паузе, но касания и ручное моргание остаются доступными.

Полигоны рук, кистей и ног следуют соответствующим деформированным слоям; остальные — опорной сетке. При пересечении кисть приоритетнее лица, лицо — волос. Фон не активен. Удержание, перемещение и несколько пальцев не считаются tap. На холсте `touch-action: pan-y`: вертикальная прокрутка разрешена, pinch/double-tap на самом холсте не запрашиваются; вне холста глобальный zoom не отключён. `?debug=1` показывает полигоны, `?qa=1` включает диагностический API.

## Как устроена анимация

- Сохранены формулы V1 для дыхания, волос, ткани и моргания, а также выражения и 13 зон V3. Голова, глаза и выражения движутся согласованно; волосы и некоторые элементы реагируют с задержкой. Небольшое изменение масштаба головы лишь имитирует приближение/отдаление, а не создаёт 3D.
- Поверх деформируемой подложки теперь находятся **отдельные прозрачные сетки** поднятой и опущенной рук и двух ног. У каждой конечности своя цепь из трёх 2D-суставов: плечо/локоть/запястье либо бедро/колено/лодыжка. Иерархия FK передаёт движение нижележащим частям; сглаженные веса изгибают сетку вокруг суставов, а не вращают отсоединённые прямоугольные фрагменты. Кисть — часть непрерывной сетки руки, не отдельные подвижные пальцы.
- Часть обуви выделена дополнительной сеткой для изменения порядка перекрытия скрещённых ног, но использует **ту же** цепь, что и соответствующая голень. Края у манжет и под юбкой плавно сходятся с подложкой. Координаты и оси — приближение к видимым частям нарисованной позы; скрытое соединение опущенной руки с кистью не восстановлено анатомически.
- У каждой конечности и каждого сустава есть ограниченное idle-движение и локальные реакции; запястье/лодыжка могут следовать с задержкой. Реакции остальных зон координируют голову, корпус, плечи и волосы. Три ограниченных варианта реакции чередуются; быстрые повторы плавно прерывают старое движение, не выстраивая очередь.
- В runtime используются производные текстуры `public/derived/jointed/`, а не новая утверждённая картинка. Статичная панель продолжает использовать утверждённый оригинал. Ресурсы собраны по маскам и частично восстановленным подложкам; их происхождение и невошедшие в runtime исследования — в [`artifacts/PROVENANCE.md`](artifacts/PROVENANCE.md).

## Ограничения

Исходник плоский и содержит перекрытия пальца с лицом, руки с волосами и скрещённых ног. Невидимые части **не были исходными слоями**: подложки приблизительные, небольшой участок дальней ноги экстраполирован, закрытая часть обуви отражена из соседних пикселей. При сильном увеличении или движении возможны неверное перекрытие, размытие, угловатая тень обуви или заметные границы. Палец отделён вместе со всей кистью, но не имеет индивидуальных суставов; выражения исключают его исходную область. Большие жесты, шаги, 3D-повороты и физика отдельных прядей не реализованы. Для достоверного широкого диапазона нужен художественно согласованный послойный исходник/дорисовка и ручная проверка.

Проверки не доказывают отсутствие всех визуальных дефектов. Физический iPhone Safari не тестировался. Многослойная сцена работает медленнее прежней общей сетки в программном рендере; измерение и его ограничения приведены в [`QA.md`](QA.md).

## Проверки и воспроизводимость

- `npm test` — математические и ресурсные тесты, включая независимость 12 суставов, граничные позы и прерывания.
- `npm run test:ui` — Pixi/WebGL в Playwright. Выберите `HERO_BROWSER=webkit`, `HERO_DEVICE=mobile|landscape`, `HERO_TEST_URL` и, для сравнения с запущенным V1, `HERO_V1_TEST_URL`.
- `npm run test:perf` — измеряет частоту `requestAnimationFrame` в iPhone-sized браузерной **эмуляции**; при необходимости задайте `HERO_TEST_URL`, `HERO_BROWSER` и `HERO_PERF_SECONDS`. Это не измерение на iPhone.
- Для автономной проверки и пересборки ресурсов установите вне репозитория Python-пакеты `numpy==2.2.6`, `opencv-python-headless==4.11.0.86`, `Pillow==11.3.0`. Запустите `python scripts/jointed-asset-test.py`, а для полной пересборки — `python scripts/build-jointed-assets.py`. Скрипт проверяет SHA исходника и пишет только в V3; результаты других версий библиотек могут отличаться. `python scripts/asset-test.py` проверяет прежние маски выражений.
- Фактические результаты, версия проверенного кода и открытые ограничения — в [`QA.md`](QA.md) и [`PROGRESS.md`](PROGRESS.md).
